# Rules

Generated by `msscan rules --format markdown`. Severity is the default; some rules raise it when the evidence is stronger (for example a dynamic import that is also called).

| ID | Name | Severity | CWE | What it means | What to do |
|---|---|---|---|---|---|
| MS101 | `pickle-dangerous-call` | critical | CWE-502 | A pickle calls a function that can run code, start processes, touch files or the network. | Do not load the file. Obtain the weights in safetensors or another format without code. |
| MS102 | `pickle-dangerous-import` | high | CWE-502 | A pickle imports a dangerous global without an observed call; the reference alone is unusual. | Do not load the file with pickle; inspect where the reference is used. |
| MS103 | `pickle-dynamic-import` | high | CWE-502 | STACK_GLOBAL takes a module or name that is not a constant string, so the import is chosen at load time. | Treat as malicious unless the producer is known; no ordinary serializer emits this. |
| MS104 | `pickle-extension-registry` | high | CWE-502 | EXT1, EXT2 or EXT4 resolve a global through the copyreg extension registry, which the scanner cannot see. | Load only in a process whose copyreg registry is known, or convert the file. |
| MS105 | `pickle-attribute-injection` | critical | CWE-915 | BUILD writes a dunder attribute such as __setstate__ onto an object, so a later BUILD calls an attacker-chosen function. | Do not load the file. |
| MS106 | `pickle-nested-loader` | high | CWE-502 | The pickle calls another deserializer (pickle.loads, torch.load, numpy.load and similar) on embedded bytes; the embedded payload is scanned and reported too. | Scan the embedded payload findings; avoid loaders that deserialize nested pickles. |
| MS107 | `pickle-unknown-call` | medium | CWE-502 | A pickle calls a global that is neither on the allowlist of known-safe constructors nor on the denylist. | Check that the module is a library you trust and that it is installed from a trusted source. |
